# Database

Drizzle ORM (v1 release candidate, relations-v2) on PostgreSQL. Schema files are in `src/server/db/schema/`; `src/server/db/schema/index.ts` re-exports them and `relations.ts` defines relations.

## Schema conventions

- Primary keys are prefixed text ids (`usr_...`, `tsk_...`) generated in the schema, not serial integers.
- For a new enum-like column use `text("status").$type<TaskStatus>()` with a TypeScript enum in `src/lib/enums/`, as `task.schema.ts` does. Do not add new `pgEnum`s: changing a Postgres enum needs a migration for every new value. (`role` on the user table is the one legacy `pgEnum`.)
- Derive validation from the table with `drizzle-valibot` (`createInsertSchema`, `createSelectSchema`) instead of writing a second schema by hand. Server-side validation is the final authority.
- Import schema types and enums; do not redefine them or compare against string literals.

## Migrations

```bash
bun run drizzle:generate   # after any change under src/server/db/schema/
bun run drizzle:migrate    # apply locally (production applies them with `bun run build:prod`)
bun run drizzle:seed       # seed development data, including the e2e users
bun run drizzle:reseed     # wipe the local database and start over (destructive, development only)
```

- Review the generated SQL before committing it, and commit the migration together with the schema change. A pre-commit hook regenerates it when schema files are staged.
- Never hand-merge `snapshot.json` or a migration. On a conflict, drop your migration, update your branch, and run `bun run drizzle:generate` again.
- Do not edit a migration that has already been applied anywhere; add a new one.

## The better-auth tables

- The auth tables (`user`, `session`, `account`, `verification`) are owned by hand in `auth.schema.ts`, not generated by better-auth's CLI. Extra user columns are declared in `src/server/auth/user-fields.ts` (server-owned, `input: false`).
- `src/server/auth/adapter-schema.ts` passes an explicit schema map to the adapter. Do not rename models with `modelName` in `auth.ts`; see [Auth](auth.md).

## Access from application code

Use the shared data-access layer (`src/functions/base-service.ts` and the per-operation files) so CASL read filters and write guards apply. Do not query tables directly from a route or component. Connections and helpers live in `src/server/db/index.ts` and `DrizzleOrm.ts`.
