# Internationalization (Lingui 6)

English (`en`, source) and Spanish (`es`). Catalogs live in `src/locales/{locale}/messages.po` and are compiled on
import by `@lingui/vite-plugin`, so there is no generated `messages.js` to commit.

## Writing messages

```tsx
import { Plural, Trans, useLingui } from "@lingui/react/macro";

<Trans>Get Started</Trans>
<Plural value={count} one="# feature" other="# features" />

const { t } = useLingui();
placeholder={t`Enter your email`}
```

Use `useLingui()` for strings (attributes, validation, errors). Use `msg` from `@lingui/core/macro` for module-level
messages and translate them at render time with `i18n._(descriptor)`.

Do not import the global `i18n` from `@lingui/core`, or `t` from `@lingui/core/macro`: on the server one global
instance is shared by concurrent requests, so one visitor's locale could leak into another's HTML. Biome
(`style/noRestrictedImports`) rejects both.

## Workflow

```bash
bun run extract        # update the catalogs from the source
bun run i18n:check     # CI: catalogs in sync (no obsolete entries) and no missing es translations
```

Line numbers are disabled in the `.po` headers so unrelated edits do not make `i18n:check` fail. Tests and stories
are excluded from extraction (`lingui.config.js`).

## How the locale is chosen

`src/lib/i18n/middleware.ts` (a request middleware) resolves the locale per request, creates a fresh `setupI18n()` and
passes `{ i18n }` through the start context. Order:

1. `?locale=es` (also sets the cookie)
2. `locale` cookie (`Path=/; Max-Age=1 year; SameSite=Lax; HttpOnly`, plus `Secure` in production)
3. `Accept-Language` by q value (`es-MX` maps to `es`)
4. `en`

`src/lib/i18n/router-plugin.tsx` wraps the router with `I18nProvider`, dehydrates `{ locale, messages }` on the server
and activates the same catalog before hydration on the client, which avoids hydration mismatches. The root route
renders `<html lang>`. `LocaleSwitcher` loads the catalog, calls the `updateLocale` server function (sets the cookie) and invalidates the router, with no full reload.

## Adding a locale

1. Add it to `LOCALES` in `src/lib/i18n/locales.ts` and to `locales` in `lingui.config.js`.
2. `bun run extract`, translate the new `.po`, then `bun run i18n:check`.

## Testing

- Unit: `src/lib/i18n/__tests__` (resolution, middleware, compiled catalogs).
- Storybook: the toolbar has a locale switch; a story can set `globals: { locale: "es" }`.
- E2E: `src/e2e/public/i18n.test.ts`.
